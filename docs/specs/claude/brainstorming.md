# 브레인스토밍 기능 명세

## 1. 개요

### 1-1. 배경

원고가 없거나 처음부터 써야 하는 일반 사용자는 빈 화면 앞에서 막막해하고 서비스를 떠나기 쉽다. 브레인스토밍 기능은 **원고 없이 들어온 사용자도 작업을 시작할 수 있는 입구**다.

### 1-2. 목표

| 항목 | 내용 |
| --- | --- |
| 대상 | 원고가 없는 사용자, 특히 작가가 아닌 일반 사용자 |
| 해결할 문제 | 첫 단어를 스스로 떠올려야 하는 막막함 |
| 기대 효과 | 일반 사용자 유입과 잔류 |
| 핵심 원칙 | 영감은 AI가 돕되, 이야기를 만드는 건 사용자가 직접 한다 |

### 1-3. LLM의 진부함 문제와 대응

LLM에게 그냥 아이디어를 달라고 하면 매번 틀에 박힌 클리셰가 나온다. 그래서 영감 키워드는 LLM이 만들지 않고 **사람이 만든 데이터에서 뽑은 키워드 풀**에서 꺼낸다(3장). LLM은 키워드를 거르고, 정리하고, 연상을 돕는 데만 쓴다.

## 2. 전체 흐름

```
브레인스토밍 보드 진입 (AI 도움 여부를 묻지 않고 항상 바로 들어감)
  ├─ [영감 카드 받기] → 카드 5장 → 끌리는 카드 선택 → 보드에 노드로 추가
  ├─ 사용자가 노드를 만들고 선으로 이으며 브레인스토밍 (필요할 때마다 AI 도움 버튼)
  ├─ 떠오른 생각을 아이디어로 따로 저장
  └─ 원고 작성 페이지에서 보드와 아이디어를 언제든 꺼내 보며 작업
```

- 처음에 "AI 도움을 받을지"를 묻는 단계는 두지 않는다. 고민할 게 하나 늘고, 한 번 고르면 되돌리기 애매하기 때문이다.
- [영감 카드 받기] 버튼은 처음뿐 아니라 브레인스토밍 도중 언제든 누를 수 있다.

## 3. 영감 카드

### 3-1. 키워드 풀

카드는 사용자가 요청할 때마다 새로 만들지 않는다. 백엔드가 **주기적으로(예: 하루 한 번) 미리 키워드 풀을 만들어 저장**하고, 사용자가 요청하면 풀에서 뽑기만 한다. 비용과 응답 속도 모두에 유리하다.

키워드에는 아래 정보를 붙인다.

| 정보 | 용도 |
| --- | --- |
| 종류 태그 | 사물 / 장소 / 인물 / 상황 / 감정. 카드 5장을 고르게 뽑는 데 씀 |
| 출처 | 사용자 원고 / 웹 트렌드. 혼합 비율 조절과 동의 철회 시 삭제에 씀 |
| 트로프 여부 | 3-4 참고 |
| 유효기간 | 웹 트렌드 키워드만 해당 |

키워드는 단어 하나("우산")보다 **수식어가 붙은 구("젖지 않는 우산")**를 우선한다. 정형화 규칙(예: 2~8자 명사구)은 구현할 때 정한다.

### 3-2. 소스 ①: 동의한 사용자의 원고

- 원고 활용에 **동의한 사용자의 원고에서만** 추출한다. 동의 문구에 "키워드 형태로 다른 사용자에게 보여질 수 있음"을 밝힌다.
- 동의를 철회하면 그 원고에서 나온 키워드도 풀에서 지운다. 이를 위해 키워드마다 어느 원고에서 나왔는지 기록한다.
- 횟수가 아니라 **몇 편의 원고에 나왔는지**로 센다.
- 아래 키워드는 제외한다.
  - 너무 많은 원고에 나온 상위 키워드 (기준: 개수 또는 퍼센트, 수치 미정)
  - 불용어 목록에 있는 단어 ("사람, 시간, 마음, 생각" 등)
  - 너무 적은 원고에 나온 단어 (예: 3편 미만). 한 사람의 고유 설정이 남에게 노출되는 것을 막는다.
  - 인명, 지명, 직접 만든 조어 같은 고유명사
- **도입 시점**: 사용자가 어느 정도 모인 뒤 적용한다. 그전에는 웹 트렌드 키워드만으로 풀을 채운다.

### 3-3. 소스 ②: 웹 트렌드

목적은 **요즘 사람들이 관심을 가지는 주제**를 반영하는 것이다.

1. 검색 서비스 API로 블로그와 커뮤니티 글의 **제목만** 수집한다. 본문은 가져오지 않는다. 사용할 API의 약관(저장·상업적 이용·호출량)은 미리 확인한다.
2. LLM이 **정치, 사건·사고, 실존 인물, 브랜드, 뉴스성 이슈**를 걸러낸다.
3. LLM 필터가 놓친 것을 잡기 위해 **금지어 사전**으로 한 번 더 거른다.
4. 남은 제목에서 키워드를 하나씩 추출해 정형화하고 풀에 넣는다.
5. 트렌드 키워드는 금방 낡으므로 **유효기간**(예: 30일)이 지나면 풀에서 뺀다.

카드에 출처는 표시하지 않는다.

### 3-4. 트로프 (진부한 아이디어) 관리

"회귀, 빙의, 계약 결혼"처럼 단어 자체는 흔하지 않아도 아이디어가 진부한 키워드가 있다. **AI는 무엇이 진부한지 판단하지 못하므로 트로프 여부를 AI가 판단하지 않는다.**

- **정의**: 트로프 = 이미 많은 사람이 쓰고 고른 것. 판단하지 않고 **센다**.
- **판별 기준**
  - 같은 장르 원고 중 몇 퍼센트에 나왔나
  - 카드로 보여줬을 때 얼마나 자주 선택됐나
  - 사용자가 카드나 AI 추천 옆의 **"뻔해요" 버튼**을 얼마나 눌렀나 (사람이 느끼는 진부함을 직접 수집)
- AI는 세기 전에 같은 뜻끼리 묶는 일만 한다 ("회귀 / 회귀물 / 과거로 돌아감" → 하나).
- 데이터가 쌓이기 전에는 팀이 만든 트로프 목록으로 시작한다.
- 트로프는 지우지 않는다. 익숙한 소재는 일반 사용자에게 좋은 출발점이 된다. 대신 **카드 5장 중 트로프는 최대 1장**으로 제한하고, 낯선 키워드와 섞이게 한다.

### 3-5. 카드 화면

- 한 번에 **5장**을 보여준다. 종류 태그별로 고르게 뽑는다.
- 선택 개수 제한은 없다. 0장(섞기만 하기)도, 5장 모두 골라도 된다.
- 고른 카드는 보드에 **서로 연결되지 않은 노드**로 추가된다.
- 원고 키워드와 트렌드 키워드의 비율은 상황에 따라 바꾼다. 사용자 수가 적을 때는 원고 키워드 비율을 낮게, 사용자가 늘수록 높인다.

### 3-6. 다시 섞기

- 섞기는 **LLM을 다시 호출하지 않고 풀에서 새로 뽑는 것**이다. 그래서 여러 번 섞어도 진부해지지 않는다.
- 사용자별로 **보여준 카드 기록**을 남기고, 이미 본 카드는 제외하고 뽑는다.
- 풀을 다 보여준 경우
  1. **가장 오래전에 보여준 카드부터** 다시 보여준다.
  2. 키워드 두 개를 붙인 **조합 카드**를 만든다 (예: "윤달" + "편의점" → "윤달에만 문 여는 편의점"). LLM은 문장을 다듬는 데만 쓴다.
- (나중에 추가) 섞기를 일정 횟수 이상 누르면 "지금 떠오르는 단어 하나로 시작해 보세요"처럼 직접 노드를 만들도록 권하는 문구를 보여준다.

## 4. 브레인스토밍 보드

### 4-1. 그래프 구조

자료구조로서의 그래프를 화면에 시각화한다. 노드는 단어, 선은 연결이다.

- 사용자가 떠오르는 단어를 **노드**로 추가한다.
- 기존 노드에서 연상된 단어는 그 노드와 **선**으로 연결한다.
- 기존 노드와 상관없이 새로 떠오른 단어는 떨어진 곳에 **별개의 그래프**처럼 둘 수 있다.
- 선은 **무방향 / 유방향** 중 선택할 수 있다.
- 선마다 **메모**를 달 수 있다 ("왜 연결했는지"를 나중에 다시 볼 수 있게).
- 노드를 만들 때 **어느 노드에서 파생됐는지(created_from)**를 저장해 생각의 흐름을 되짚을 수 있게 한다.

### 4-2. "별개의 그래프"의 저장 방식

"그래프"를 데이터 개체로 따로 만들지 않는다. **보드 하나에 노드 목록과 선 목록만 저장**한다. 서로 연결되지 않은 노드 묶음은 화면에서 자연스럽게 별개의 그래프로 보인다.

```json
{
  "board_id": "b1",
  "nodes": [
    { "id": "n1", "label": "등대", "created_from": null },
    { "id": "n2", "label": "어머니", "created_from": "n1" },
    { "id": "n3", "label": "우산", "created_from": null }
  ],
  "edges": [
    { "a": "n1", "b": "n2", "directed": false, "memo": "기다림" }
  ]
}
```

위 예시에서 등대–어머니와 우산은 연결되어 있지 않으므로 별개의 그래프 두 개로 보인다. 이렇게 하면 두 묶음을 이을 때는 선만 추가하고, 선을 지워 끊어질 때도 선만 지우면 된다. 그래프 단위로 합치거나 쪼개는 처리가 필요 없다.

### 4-3. 보드 안의 AI 도움

사용자가 **버튼을 누를 때만** 동작한다. 구체적인 도움 범위는 운영하면서 계속 개선한다.

| 기능 | 동작 |
| --- | --- |
| 연상 노드 추천 | 노드를 고르고 버튼을 누르면 연상 단어 후보 노드가 반투명하게 뜬다. 클릭하면 확정, 무시하면 사라진다 |
| 두 노드 연결 질문 | 멀리 떨어진 두 노드를 고르면 "만약 이 둘이 연결된다면?" 질문을 하나 던진다 (예: "등대지기가 비 오는 날에만 우산을 판다면?") |

- 연상 추천 프롬프트에는 **보드에 이미 있는 노드를 넣어 중복을 막고**, 키워드 풀의 단어를 몇 개 섞어 진부함을 줄인다.
- 두 노드 연결 기능은 답이 아니라 **질문**을 준다. 이야기는 사용자가 직접 만든다는 원칙을 따른다.

## 5. 아이디어 기록

브레인스토밍에서 영감을 받았지만 아직 전체 이야기는 정하지 못한 단계를 위한 기능이다.

- 떠오른 생각을 **아이디어**로 따로 저장한다. 구체적이지 않아도 된다.
- 보드에서 노드 몇 개를 골라 **"아이디어로 묶기"**를 하면, 그 노드들을 참조하는 아이디어가 만들어진다. 나중에 아이디어가 어떤 단어들에서 나왔는지 따라갈 수 있다.
- 아이디어는 **사용자가 직접 쓰는 것이 기본**이다. 원하는 사용자를 위해 AI 도움(선택)을 둔다.
  - 고른 노드와 선 메모를 바탕으로 몇 줄짜리 아이디어 문장을 제안한다.

## 6. 원고 작업 중 참조

- 원고 작성 페이지에서 **브레인스토밍 보드와 아이디어를 언제든 쉽게 꺼내 볼 수 있게** UI/UX를 설계한다. 원고를 쓰면서 계속 확인하고 대조할 수 있어야 한다.
- AI 도움(선택): 아이디어를 원고의 이야기 속에 **어떻게 적용할지 추천**한다. 이때 프로젝트의 기존 설정 데이터(캐릭터 속성, 세계 규칙)를 함께 넣어 맥락에 맞는 제안이 나오게 한다.

## 7. 데이터 소속

- 브레인스토밍은 원고(프로젝트)가 생기기 전에 시작한다. 따라서 보드와 아이디어는 **프로젝트가 아니라 사용자에게 속한다**.
- 보드·아이디어와 프로젝트는 **N:M으로 연결**한다. 보드 하나에서 원고 두 편이 나올 수도 있고, 원고 하나가 보드 여러 개를 참고할 수도 있다.

## 8. AI 제안 품질 관리

아이디어 문장 제안과 원고 적용 추천처럼 정답이 없는 출력은, 프롬프트를 바꿀 때 **좋아졌는지를 숫자로 확인**하고 배포한다. 사용자에게 보이는 기능이 아니라 개발용 측정 도구다.

1. 팀원들이 가상의 브레인스토밍 보드를 20개쯤 만든다 (노드, 선, 선 메모 포함).
2. 기존 프롬프트(A)와 고친 프롬프트(B)로 각 보드의 제안을 받는다.
3. 채점 LLM(judge)에게 보드, A, B, 채점 기준을 주고 어느 쪽이 나은지와 그 이유를 받는다.
4. B가 더 많이 이기면 B를 채택한다.

채점 원칙

- 채점 기준(루브릭)은 **팀이 정한다**. 예: 사용자 노드를 실제로 엮었는가, 선 메모의 의미를 살렸는가, 장면이 떠오를 만큼 구체적인가.
- **셀 수 있는 기준은 코드로 센다** (사용한 노드 수, 메모 단어 포함 여부). LLM에게는 주관적인 기준만 맡긴다.
- LLM의 편향을 막는다. A와 B의 순서를 바꿔 두 번 묻고 두 번 다 이긴 경우만 승리로 친다. 루브릭에 "길이는 판단하지 않는다"를 적는다.
- 처음에는 팀원이 직접 판정한 결과와 judge의 판정을 비교한다. 대부분 일치할 때부터 judge에게 맡긴다.
- 진부함은 judge가 판단하지 않고 3-4의 트로프 기준으로 확인한다.
- 기존 `evals/judge.py`(정답 포함 여부 채점)의 구조(LLM 호출 + 응답 스키마 + 루브릭 + 판단 이유)를 재사용하되, 채점 방식은 "둘 중 어느 쪽이 나은가"로 바꾼다.
- (선택) 실제 서비스에서도 제안을 5개 만들고 judge가 고른 상위 2개만 보여줄 수 있다. 측정으로 효과를 확인한 뒤 도입한다.

## 9. 역할 분담

| 담당 | 내용 |
| --- | --- |
| prolog-ai (이 저장소) | 원고 → 키워드 추출, 트렌드 제목 → 필터링·정형화, 같은 뜻 키워드 묶기, 연상 노드 추천, 두 노드 연결 질문, 조합 카드 문장 다듬기, 아이디어 문장 제안, 원고 적용 추천, 품질 측정 도구 |
